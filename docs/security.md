# 安全模型

## 信任链

从可信渠道取得客户端和初始公钥根。根包含 version、expiresAt、threshold 及 key ID → Ed25519 公钥。初始单项目专属密钥 threshold=1；软件支持多签根和索引，但首版托管发布自动化按单密钥配置。

索引签名对 `foundry:index:v1\n` 的 UTF-8 字节及原始 index.json 字节拼接后进行 Ed25519 签名。根更新使用 `foundry:root:v1\n`，客户端产物清单使用 `foundry:release:v1\n`。不能重新格式化已签名 JSON。签名文件是 `{keyId,signature}`，signature 为 hex；客户端也可读取签名数组。

客户端先验签再解析索引，拒绝过期索引、未知 key、低于本机最高序号的索引。索引包含 ZIP 大小与 SHA-256；安装检查 ZIP 和 files.json，运行检查持久化的清单摘要及全部文件，然后复制到本次运行快照。更新先暂存、验证并原子切换状态，失败不破坏既有版本。并发安装用文件锁串行化。

本地状态、根文件和用户目录必须由当前用户保护；签名机制不抵抗同用户恶意进程篡改客户端、状态或公钥。首次安装的新机器无法知道历史最高序号，依赖签名有效期和可信时间；系统时钟被回拨会削弱新鲜度保护。同序号的合法签名索引视为同一发布批次，发布服务必须保证序号唯一且只增。

## PR 与生产密钥

PR 不得取得任何签名私钥，不能通过带 secrets 的 pull_request_target 执行 PR 内容。CI 无密钥构建和测试；合并后按固定提交构建候选产物，生成 release-manifest.json 摘要和审批摘要。受保护签名环境由维护者核对提交和候选清单 SHA-256 后审批。

签名 job 从受保护分支检出可信签名工具与脚本，只将候选包当数据核对摘要，不运行候选包中的程序、JS 或构建脚本。工具源文件、Cargo.toml/Cargo.lock、Cargo 配置、工作流、发布脚本与公钥根同样需要可信审核；保护主分支和配置管理员是此模型的前提。仅配置 secret 不会自动启用人工审批，必须设置 GitHub Environment required reviewers。

### 扩展 presubmit 的防护

- 使用 `pull_request`、只读 `contents`、`persist-credentials: false`；不使用 `pull_request_target` 执行 PR 代码。不授予 OIDC、发布权限或受保护 Environment，不向测试传递任何生产 secret。
- PR 矩阵由基准提交中的规划器解析，平台映射固定为 GitHub 托管 runner。版本名、ID、路径及配置字段严格校验，拒绝 shell 命令、重复键、YAML 引用、自托管 runner。矩阵值经环境变量传入命令，不插入 shell 源码。首次启用前须先将可信规划器合入基准分支；缺失时失败，不回退执行 PR 规划器。
- 每个扩展/版本/平台使用独立临时 runner，设任务超时和并行上限，不在签名 runner 执行扩展；原生构建及能力测试使用环境变量白名单，剔除 GitHub、云和签名凭据。测试中临时生成的密钥仅用于测试，不能签署生产索引。
- 历史版本目录不可修改或删除。发布先验证旧索引签名，再绑定历史数据摘要、候选清单摘要与提交；旧包 URL、哈希、大小保持不变，撤回状态通过新的签名索引生效。

这些措施不把原生代码变成安全沙箱。恶意构建脚本、可执行文件或动态库仍可读取同一 runner 上可访问的文件和网络，并可能接触 Actions 任务自身的短期令牌；只读令牌及临时 runner 限制其影响范围，环境白名单不能阻止读取父进程或磁盘。不要向这些 runner 安装私有凭据、挂载宿主目录或替换为持有凭据的自托管机器。GitHub 不会向 fork PR 提供普通仓库 secrets，但仓库内部 PR 也必须遵循不注入 secrets 的配置。

生产私钥只能放在限制默认分支、需要维护者审批的 `release-signing` Environment secret 中，不能放仓库级/组织级可被 PR 作业使用的 secrets。密钥掩码不能阻止恶意代码编码后外传密钥。审核工作流变更、主分支保护和 Environment 规则是必须由管理员实际启用的边界，无法仅靠仓库里的 YAML 保证。

## 权限与隔离

默认拒绝未声明或未授权的桥接能力。升级需要新增权限时重新授权。纯 JS 有 QuickJS 时间、内存及宿主访问限制。`process.spawn` 与 `native.call` 允许可信代码以当前用户权限运行；独立进程用于错误和崩溃隔离，不限制所有文件、网络、子进程或系统调用。不得向用户承诺原生代码强沙箱。

ZIP 拒绝路径穿越、重复条目、链接、设备、大小写碰撞和超限解压。命令行不拼接 shell，FFI 拒绝非法类型和裸指针。实现采用限额而不是任意大小缓存；复杂 Schema/恶意压缩文件仍应只接受维护者审核的扩展。权限确认不是代码审计。

## 轮换与恢复

1. 离线生成新根（version 必须正好 +1）。
2. 旧根阈值和新根阈值都必须对同一原始根文件签名，组成签名数组。
3. 用 `foundry trust rotate --root next-root.json --signatures root-signatures.json` 更新本机数据目录的根文件；此命令不接受额外的 --trust-root，避免更新错误位置。
4. 发布端在新根分发和核对完成后切换签名 key ID；仍在使用旧客户端的用户需要先取得根更新。

根过期或旧私钥丢失时不能自动信任新根，需要通过已建立的独立可信渠道核对并人工替换；不实现“下载一个新公钥就信任”的恢复捷径。管理员发布工具的 `verify --allow-expired` 只允许核对过期的历史索引签名用于发布序号检查，仍检查根有效期，客户端没有此开关。

本地缓存包在卸载后保留为不可变对象，以免破坏正在运行的快照；首版没有垃圾回收命令。用户可在没有客户端运行时删除整个专属测试数据目录，不应手动删改已安装包文件。

签名索引的 `withdrawnPackages` 保留已撤回包的原始记录，客户端只从 `packages` 选择安装。撤回后恢复发布会复用原来的包及 URL，不允许借撤回重写历史二进制。

## PR diff 输出

PR diff 作业与测试一样只有只读权限，不访问签名 Environment，也不使用高权限 `workflow_run` 或 `pull_request_target` 来评论 PR。报告写入 Actions Summary 并上传 artifact，匹配 BCR 的展示方式。报告生成器从可信基准检出，只将候选 Git 对象当数据处理；转义 Markdown/HTML，使用不能被内容提前闭合的代码围栏，不将 diff 内容输出到 shell 源码或 Actions 命令日志。文件/报告限额用于控制资源占用，报告不能代替完整代码审查。

可信工具检出目录与 PR 候选目录使用工作区下的两个同级目录（trusted/candidate），不会将可信工具检出到候选目录内部，避免 PR 提交同名目录或符号链接影响可信工具和基准比较。
