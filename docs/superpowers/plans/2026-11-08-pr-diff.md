# PR Diff and Platform Checks Implementation Plan

> **For agentic workers:** Use executing-plans to implement inline; use a fresh final reviewer. Steps use checkbox syntax for tracking.

**Goal:** Give extension PRs a BCR-style review diff and explicit results for four platform checks.

**Architecture:** A trusted-base Python tool reads committed Git objects as data, compares new versions to the previous baseline version, and emits bounded Markdown and JSON reports. Read-only PR jobs publish the report to Actions Summary/artifacts and attach per-platform test logs; one stable gate aggregates outcomes.

**Tech Stack:** Python 3.12, Git, GitHub Actions, existing Rust/QuickJS extension runner.

**Spec:** User request: “原来pr是支持diff输出等功能的，也加上去，另外也需要多平台ci测试”; reference /root/projects/bcr/.github/workflows/generate_diff.yml.

## Global Constraints

- Never give PR tests production secrets, write tokens, signing environments, or self-hosted runners.
- Trusted report code comes from PR base; candidate files are data, never executed to generate diffs.
- Preserve Linux x64/arm64, macOS arm64 and Windows x64 runner matrix.
- Do not post PR comments or publish externally; Summary and artifacts match the BCR reference.

## Review Focus

- New versions in one PR must compare to trusted baseline versions, not misleading candidate history.
- Deletions, immutable-version edits and yanks remain visible even when matrix validation fails.
- Malicious Markdown, filenames, symlinks, binary files and large diffs must not execute or corrupt reports.
- Invalid/missing bases fail closed rather than emitting a misleading empty diff.
- Failed/skipped platform jobs must not turn the stable gate green.
