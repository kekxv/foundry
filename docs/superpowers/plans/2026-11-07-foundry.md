# Foundry Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付支持三类正式扩展的跨平台客户端、可信分发链路和自动部署官网。

**Architecture:** Rust 客户端从签名索引安装按平台打包的扩展，QuickJS 加载已验证的 JS 模块，通过宿主桥接调用受控能力。命令行和 libffi 调用在子进程执行，索引及包摘要由受保护的 GitHub 发布流程签署，官网从相同目录数据生成。

**Tech Stack:** Rust stable、Cargo workspace、rquickjs、libffi、libloading、serde/serde_json、jsonschema、reqwest/rustls、ed25519-dalek、SHA-256、ZIP、Astro、TypeScript、GitHub Actions。

**Spec:** [设计规格](../specs/2026-11-07-foundry.md)

## Global Constraints

- 客户端使用 Rust + rquickjs；动态库通过 libffi 调用。
- 扩展类型为 javascript、executable、native-library。
- 首批正式发布 text-utils、file-digest、native-math，附源码和文档，不另建 examples 目录。
- 目标平台为 windows-x64、macos-arm64、linux-x64、linux-arm64；首版 Linux 以 glibc 环境为基线，musl 和 Windows ARM64 后续支持。
- 动态库首版支持默认平台 C ABI，C++ 通过 extern C 包装；暂不支持任意 C++ ABI、变参、按值结构体及回调。
- PR 自动检查；审核批准后，对固定提交对应的内容由受保护流程签名。签名私钥不得进入外部 PR 执行环境。
- 官网使用 Astro，自动构建并推送 gh-pages，展示扩展目录和编写指南。
- 签名流程不检出、不运行候选扩展源码或其构建脚本；签名器与信任根修改需专门审核。
- 首版不承诺原生代码强沙箱，不做源码包管理或扩展依赖求解。
- 对外使用 UTF-8 JSON，文件名和平台约定写入规范；依赖锁文件提交，工具链和 Actions 固定版本或提交。

## Review Focus

1. 外部 PR 或旧提交替换待签名产物：签名必须绑定审核过的固定提交与完整产物哈希，过期审批不能授权新提交（任务 7）。
2. 安装包路径穿越、符号链接、重复条目及解压炸弹：安装不得写出暂存目录，失败不得破坏已安装版本（任务 2、6）。
3. JS 无限循环、未完成 Promise、模块逃逸：内存与总执行时间受限，所有模块导入必须留在已校验包内（任务 3）。
4. FFI 参数或 ABI 不匹配：拒绝越界、非法句柄、未声明符号；原生进程崩溃或超时后主客户端仍可运行（任务 5）。
5. 陈旧索引、权限升级、平台差异：拒绝回滚和过期索引；升级新增权限需重新授权；空格、中文路径和各平台产物均有覆盖（任务 2、4、6、7）。

## 固定接口约定

### 扩展与分发格式

- `manifest.json` 包含 `schemaVersion: 1`、`id`、SemVer `version`、`description`、`type`、`entry`、`platforms`、`permissions`、`capabilities`，可选 `executables` 或 `libraries`。
- `capabilities` 是能力名到 `{ description, export, input, output }` 的映射；`input/output` 使用 JSON Schema Draft 2020-12，禁用远程 `$ref`，限制 schema 深度和大小。
- 能力函数接收一个 JSON 值，返回 JSON 值或解析为 JSON 值的 Promise；`undefined`、循环引用、非有限数值和不可序列化对象返回明确错误。
- `entry` 和所有包内资源必须是规范化相对路径，禁用绝对路径、`..`、驱动器前缀及包外链接。
- 纯 JS 包使用 `platform: any`；原生包按平台各发一个 ZIP。ZIP 包含 manifest、JS、原生产物及资源，`files.json` 列出除自身外全部文件的路径、大小和 SHA-256。
- 已签名索引绑定包 ID、版本、平台、ZIP 大小、SHA-256 和下载 URL。安装时核验 ZIP 哈希并验证 `files.json` 精确覆盖文件集合；运行前重新校验，拒绝额外文件和链接。
- 数据目录使用操作系统用户数据路径；每版本安装目录不可原地更新。可写数据置于包目录之外。

### 运行时及宿主桥接

```rust
// 类型定义放在实际消费它们的 crate；跨 crate 的共有 DTO 放 core。
validate_manifest(bytes: &[u8]) -> Result<Manifest, FoundryError>
validate_input(manifest: &Manifest, capability: &str, value: &Value) -> Result<(), FoundryError>
run_extension(package: &VerifiedPackage, capability: &str, input: Value,
              limits: RuntimeLimits, grants: &PermissionGrants) -> Result<Value, FoundryError>
install_extension(id: &str, version: Option<&str>, grants: &PermissionGrants) -> Result<InstalledPackage, FoundryError>
```

- `RuntimeLimits` 默认：QuickJS 堆 64 MiB、栈 1 MiB、包含 Promise 与子进程等待的总时间 30 秒，单次 JSON 输入/输出最大 1 MiB。测试使用更短限额。
- `PermissionGrants` 是调用者授权的权限及路径范围，扩展只能申请其 manifest 声明的权限，默认拒绝。CLI 在交互安装时确认，非交互使用显式授权参数；授权持久化并绑定扩展 ID，升级核对权限增量。
- `host.exec(executableId, args, options?) -> Promise<{ exitCode, stdout, stderr }>`：只解析 manifest 中的可执行文件 ID，不经过 shell。`options` 首版仅支持 `timeoutMs`，不得超过运行总限额；输出合计上限 1 MiB。可执行文件运行权限是对原生代码执行的授权，不代表 OS 沙箱。
- `host.library(libraryId).call(symbolId, args) -> Promise<JsonValue>`：只调用 manifest 中声明的符号；资源由 worker 生命周期管理，不把指针地址暴露给 JS。
- `host.fs.readText(relativePath)` 与 `writeText(relativePath, text)`：仅访问获准的扩展数据目录，使用防链接逃逸的路径检查；文件路径越界返回权限错误。
- JS 模块只支持包内相对导入，禁止 Node 内置模块、URL 导入、包外导入；不向扩展暴露 QuickJS std/os 模块。
- worker 与主进程通过带长度边界的 JSON Lines 请求/响应通信，协议包含版本和 requestId；子程序 stdout 不混入协议。超时杀死工作进程及其子进程树，无法清理应返回明确错误。
- 错误对象统一 `{ code, message, details? }`，CLI 失败退出非零；`--json` 保持 stdout 为机器可读结果，诊断写 stderr。

### FFI 首版类型

- 标量：`void`（仅返回值）、`i32`、`u32`、`f64`；32 位整数严格检查范围和整数性。
- `cstring` 输入拒绝内含 NUL；`buffer` 输入用字节数组表示；由桥接层在本次调用期间持有存储并按声明展开为 `pointer + size_t`。
- 首版不返回原生指针或原生分配的字符串/缓冲区；需要此能力时另行设计长度、所有权、释放和不透明句柄协议，避免隐式猜测内存归属。
- 首版不接受 JSON 中的裸指针、不推断函数签名；`abi: c` 映射平台默认 C ABI，错误声明本身仍可能使 worker 崩溃。
- `native-math` 正式扩展仅依赖标量接口：`add(i32, i32) -> i32`、`hypot(f64, f64) -> f64`；扩展中对加法范围提前校验。

**Interfaces:** 消费验证后的正式索引和扩展元数据，生成首页、目录、详情页和文档；未发布扩展不伪装成可安装扩展。

- [ ] 建立 Astro 静态站，首页提供产品说明、平台安装入口；扩展详情展示类型、能力输入输出、平台、权限、版本和源码链接。
- [ ] 编写三条从零开发路径，直接引用 `extensions/` 正式源码：纯 JS、命令行、libffi 动态库。文档包含本地开发调用、打包、PR、审批、签名、发布及错误排查；开发加载使用单独 `foundry dev run <path> ...` 命令并明确本地源码信任边界，不影响正式安装验签。
- [ ] `dev run` 复用格式验证、权限与运行限制，只绕过远程索引来源要求；测试禁止正式 `run` 接受任意目录或走开发路径。
- [ ] PR 仅运行站点构建和链接检查；主分支及正式发布触发构建，配置仓库子路径 base，部署凭据仅在最终推送 gh-pages 的 job 可用。使用专用部署 action 更新 gh-pages，禁止扩展构建脚本获得写权限。
- [ ] 签名索引作为受控部署输入复制到站点，不由页面脚本重写；官网与索引使用同一次原子部署，防止站点发布擦除索引。未有正式索引时首页显示尚未发布，文档可正常部署。
- [ ] 运行 `npm ci --prefix website`、`npm run check --prefix website`、`npm run build --prefix website` 与链接检查；检查手机和桌面视图、项目子路径和安装命令，不编造下载链接。
