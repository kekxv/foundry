# Foundry 设计规格

状态：方案已确认，具体接口由实施计划固定；当前尚未实现。

## 目标

构建跨平台扩展分发与运行系统。用户从正式索引安装所需功能，通过统一 JSON 接口调用扩展。扩展作者使用 JavaScript 描述和包装功能，客户端嵌入 QuickJS 执行模块，支持 Promise 与 async/await。

## 已确认范围

- 客户端使用 Rust + rquickjs；动态库通过 libffi 调用。
- 扩展类型为 javascript、executable、native-library。
- 首批正式发布 text-utils、file-digest、native-math，附源码和文档，不另建 examples 目录。
- 目标平台为 windows-x64、macos-arm64、linux-x64、linux-arm64；首版 Linux 以 glibc 环境为基线，musl 和 Windows ARM64 后续支持。
- 动态库首版支持默认平台 C ABI，C++ 通过 extern C 包装；暂不支持任意 C++ ABI、变参、按值结构体及回调。
- 发布声明类型、能力、输入输出、平台、权限、入口；动态库额外声明符号和类型。
- 官网使用 Astro，自动构建并推送 gh-pages，展示扩展目录和编写指南。
- PR 自动检查；审核批准后，对固定提交对应的内容由受保护流程签名。签名私钥不得进入外部 PR 执行环境。
- 客户端验签并校验产物哈希；密钥可轮换，索引包含序号和过期时间。

## 第一阶段验收

在目标平台安装客户端，从正式索引安装、调用、更新和卸载三类扩展；错误签名、被改动文件、非法路径和非法 FFI 参数被拒绝。开发者能够依据正式扩展源码和文档编写扩展。

## 安全边界

签名证明发布授权和完整性，不证明扩展无恶意。QuickJS 的时间、内存和宿主能力限制只约束 JS。命令行及动态库运行于子进程；进程隔离用于故障隔离，不等同于文件、网络或系统调用沙箱。首版如需执行原生代码，必须明确取得对应执行权限；不得宣传为原生代码强沙箱。

## 实施假设

- 首版公共 GitHub 仓库，GitHub Releases 存放版本产物，gh-pages 同时托管站点与签名索引。
- 包 ID 全局唯一且仅允许小写 ASCII 字母、数字及连字符；首版单仓库维护。
- 不自动按能力安装未知提供者，调用以显式扩展 ID 和能力名为准。
- 无依赖扩展优先，首版不做扩展依赖求解。
- 编写、测试和本地构建可独立完成；真实仓库地址、GitHub 环境审批规则与发布密钥在上线配置时接入。
