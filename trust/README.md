# Production trust configuration

Generate an Ed25519 key pair on a trusted machine. With OpenSSL, run these commands from the repository root.

```sh
openssl genpkey -algorithm ED25519 -out ../foundry-private.pem
openssl pkey -in ../foundry-private.pem -pubout -out ../foundry-public.pem
cargo run --locked -p foundry-release -- trust-root --public-key ../foundry-public.pem
```

1. Set the full contents of `../foundry-private.pem` as the `FOUNDRY_SIGNING_KEY` secret in the protected `release-signing` GitHub Environment. Keep the private PEM outside the repository. Hex seeds generated by `foundry-release keygen` remain supported.
2. Set the Environment variable `FOUNDRY_KEY_ID` to `foundry-production` and commit the **public** `trust/root.json`. If you use `--key-id` when creating the trust root, use that same ID in the Environment variable.
3. Require reviewers and default-branch-only deployments for `release-signing`. Protect main, workflows, signer source, Cargo configuration/lockfile and this trust directory. Configure required reviews via repository rules/CODEOWNERS with your real maintainer identities.
4. Distribute the root fingerprint through a trusted channel.

Do not use the hard-coded keys from tests for production. See `docs/security.md` and `docs/publishing.md` for rotation and recovery.
