# Production trust configuration

Generate an Ed25519 private key on a trusted machine.

```sh
openssl genpkey -algorithm ED25519 -out ../foundry-private.pem
```

1. Set the full contents of `../foundry-private.pem` as the `FOUNDRY_SIGNING_KEY` secret in the protected `release-signing` GitHub Environment. Keep the private PEM outside the repository. Hex seeds generated by `foundry-release keygen` remain supported.
2. Require reviewers and default-branch-only deployments for `release-signing`. Protect main, workflows, signer source, Cargo configuration/lockfile and this trust directory. Configure required reviews via repository rules/CODEOWNERS with your real maintainer identities.
3. Distribute the root fingerprint through a trusted channel.

The first signed release derives the public root in the protected environment and publishes it as `registry/root.json` on GitHub Pages. Subsequent releases reuse that file. The default key ID is `foundry-production`. Existing installations that use a different ID can set the optional `FOUNDRY_KEY_ID` variable in the signing environment.

Do not use the hard-coded keys from tests for production. See `docs/security.md` and `docs/publishing.md` for rotation and recovery.
